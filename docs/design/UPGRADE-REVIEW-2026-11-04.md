# 客户端升级流程审查 · 2026-11-04

审查范围：版本检查、下载和 SHA-256 校验、macOS 应用身份与签名检查、停止旧 Portal、安装助手交接、应用替换与重启、运行时回滚、取消和失败重试、诊断导出。改动已写入源码；尚未打包或发布。

## 已修复的问题

| 优先级 | 触发条件与影响 | 修复与验证 |
| --- | --- | --- |
| P1 | macOS 原先仅等待 shell 的 `spawn` 事件便退出客户端。脚本缺失、无法执行或早期失败时，旧客户端可能已退出，升级却没有开始。 | 安装脚本进入等待阶段后写入带 PID 的就绪确认；主进程检查提前退出与超时。失败时取消并停止该次助手。真实 shell 测试覆盖提前退出、超时、取消、父进程退出后继续安装，以及替换/启动失败回滚。 |
| P2 | 两次下载请求在版本检查完成前进入，都会通过原来的空闲判断。检查结果共享，但会分别创建安装暂存目录并覆盖交接对象；检查期间的取消也可能丢失。 | 在首次异步操作前占用下载状态，检查后验证取消信号，交付安装对象前再次检查取消/退出。真实主进程与 preload 测试确认并发只创建一个安装对象，取消检查不会进入下载。 |
| P2 | 安装前清理将插件宿主标记为永久关闭；交接失败后客户端和 Portal 恢复，插件宿主仍不可用。 | 失败路径显式恢复插件宿主，串行处理并保证重复恢复不会重启多个进程。真实 Cordis 子进程测试确认路由恢复、配置保留和恢复幂等。 |
| P2 | 安装助手日志位于 `client-updates`，原诊断包没有收集这一目录，无法分析交接或替换阶段的失败。 | 收集助手日志及每次尝试的状态 JSON，继续脱敏；排除安装包、脚本、配置与凭据。归档测试验证内容与过滤规则。 |

此前已修复的旧安装记录死锁也纳入回归：暂停的 subagent/Portal 启动不再阻断新安装；本地运行时回滚先于网络检查；失败恢复允许当前客户端手动重试；接续安装保留旧服务的启停偏好。

本轮在 macOS 上执行并通过以下测试，合计 119 项；另有 2 项 Windows 专用下载测试在当前平台跳过：

`node tests/update-recovery-electron.mjs` 的 4 个场景全部通过：暂停安装、离线回滚、失败回滚后手动重试，以及下载并发/取消/交接失败后再次安装。测试使用生产主进程、preload 与 IPC；网络、凭据、系统停止命令和安装暂存边界使用隔离测试实现，不替换日常应用。

TypeScript 检查和 `git diff --check` 通过。同次排障前轮已通过 4 项 macOS 原生 Portal 升级测试，包括真实系统服务替换、离线就绪检查、坏候选版本回滚及旧进程退出。

## 发布验证边界

本轮未在 Windows 实机执行安装，也未构建包含本轮改动的正式签名安装包。不能将临时签名或隔离入口测试等同于正式包整包升级。

发布工作流新增生产入口恢复测试和 macOS 签名应用替换/重启测试，并保留原有 macOS 签名包预检、Windows 原生服务回滚与 NSIS 升级测试。新版本发布必须等待这些平台检查成功；本轮未触发远端发布流程。
