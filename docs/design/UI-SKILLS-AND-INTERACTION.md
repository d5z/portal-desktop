# 客户端交互优化与 UI skills 选型

调研日期：2026-10-29。参考来自本机 Muse、Grok Bot 的实际界面操作，以及下列项目的官方仓库。

## 2026-10-30：篝火、围炉、私信排版修正

按用户要求取消社交页面固定最大宽度与居中窄栏：三页随工作区展开，宽屏两侧保留 24px 内边距，窄窗缩小边距。筛选、加载数量合为一行，缩短首条消息前的空白；围炉保留房间列表/消息分栏，在窄工作区改为横向房间列表。标题和筛选共用一个吸顶容器，不依赖固定 top 偏移，避免文字和成员控件重叠。窄窗的发言按钮保留可访问名称，以已有铅笔图标呈现，搜索与操作尽量保持同一行。

引用默认转换为纯文字的两行摘要，移除 Markdown 标记和多余空行，点击仍可查看已加载原文和跳转；完整正文、复制、回复功能保留。私信的收到/发出消息分别靠左/靠右，自适应长链接、表格与展开后的正文。

`test:town-feed-layout` 使用真实工作区和 Town 模型，覆盖 1920、1440、900、435px，浅色/深色、引用和正文展开收起、菜单复制、筛选、私信方向、滚动吸顶及无水平溢出；已加入 test:all。代表性长引用在 1440px 下由 310px 降至约 68px，篝火首条消息与筛选栏之间的间隔由约 103px 降至约 37px。类型检查、现有 Muse 工作区矩阵、隔离 Electron 菜单/剪贴板回归、54 项 Town/消息时间单元测试均通过。截图位于 test-results/town-{bonfire,firesides,mail}-after-*.png。

已引入 ahooks 并按业务边界收拢监听、合并视口更新、修正 Effect 依赖，增加 Hooks lint 与 StrictMode 生命周期回归。选型、事件所有权和改动前后实测见 [CHAT-HOOKS.md](CHAT-HOOKS.md)。

## 2026-10-30：Muse 消息计数与滚动性能复查

返回底部控件改为浅蓝胶囊、动态“N条消息”和向下箭头。数字按当前视口下方尚未完整显示的实际气泡计数，跨时间分隔和工具活动不增加条数；同一气泡流式续写不算新消息。只有工具状态或底部留白在视口外时显示“最新消息”，避免虚构“1条消息”或显示“0条消息”。底部自动隐藏；点击恢复跟随，并将已展开的历史收回最近 40 项窗口，历史数据仍在缓存中，可再次向上加载。

本轮发现并修复：
- JumpToLatest 与滚动控制器各自观察容器及整列子节点。移除按钮自己的 ResizeObserver、MutationObserver、scroll 监听，通过滚动控制器的细粒度订阅只刷新按钮。
- 阅读锚点和左侧索引逐条调用 getBoundingClientRect。改为按显示顺序二分定位，索引滚动更新合并到每帧一次；阅读锚点不再依赖 Map 插入顺序，前插历史后也按页面顺序定位。
- 离开底部的直接滚动原先只会开启、不会关闭跟随锁，下一次内容增长可能拉回底部。现在根据真实底部距离更新；编辑控件与菜单内的按键不再改变阅读跟随状态。
- 点击返回底部后仍挂载所有已展开历史。现在收回到最近一页，并取消待完成历史加载的旧窗口恢复，避免旧请求重新展开历史。

审查覆盖：实时分段与同轮合并、流式停止/回放、历史排序去重、分页前插、图片和富文本延迟变高、直接滚动/滚轮/键盘、窗口缩放、返回底部恢复跟随、草稿保留。既有流式写入已经按 animation frame 合并，Markdown 高亮在流式结束后执行，普通消息不会触发智能 UI 的重复解析，保留这些路径。

验证：46 项滚动边界、历史窗口和流式历史单元测试通过；类型检查、资源构建、chat-scroll、chat-history-window、chat-react、chat-render-performance 通过。视觉截图覆盖浅色、深色、435px 窄窗口，路径 test-results/chat-jump-muse-*.png。

同一受控流式 fixture 前后对比：消息几何读取 11,860 → 1,529（减少约 87%）；返回底部后挂载消息 81 → 41；帧间隔 P95 17.6ms → 17.2ms，两次均无 long task。测试约 132 帧，不能据此证明整窗原生拖动卡顿完全解决。连续向上翻阅时仍保留已展开历史以保护阅读位置，尚不是双向完整虚拟列表；大量历史持续展开后的内存占用仍需单独压测。

## 2026-10-30：对话流时间与划词引用

按用户提供的 Muse 截图调整聊天阅读层级：首次可见消息、相邻消息相隔至少 5 分钟或跨本地日期时，显示一行居中时间；气泡不再逐条重复时间。Being 对话不再显示重复姓名，仍保留系统、场景与中断状态；Town 多人会话保留作者。缺少有效时间的消息不伪造日期。分隔在显示层计算，删除运行时旧的重复时间分隔插入。

聊天、篝火、围炉、私信共用按需挂载的气泡菜单：仅显示简短日期时间和“复制”。删除“回复”入口及其回调、DOM 克隆与文本提取逻辑。移除作者、重复的复制选区和复制时间入口；同一个“复制”有选区时复制选中文字，否则复制整条消息。完整时间留在时间行的悬停提示中。菜单采用 220px 宽、20px 圆角、44px 操作行及一致线条图标。支持 Shift+F10、方向键、Escape、复制失败重试、窗口边缘约束和对话框顶层展示；输入框、链接和文件仍使用原有编辑/文件操作。

聊天划词浮层改为“添加到聊天 ⌘L”（非 Mac 为 Ctrl L），点击或快捷键直接在当前草稿后追加纯文字并聚焦输入框，保留已有文字和附件，不开启一起看面板、不发送消息。划词仅添加用户选中的文字，不生成引用块；保留换行和文字中的特殊符号。富文本插入保留当前草稿格式与撤销记录。其他页面原有的显式“一起看”功能保留。

通用编辑菜单按目标授权：输入框提供编辑，实际选中的正文仅提供复制，有效文件入口提供预览；页面空白、时间、普通按钮、标题不再创建菜单或拦截默认行为。保留一个委托监听处理动态输入框与弹窗，四个关闭监听仅在菜单打开期间存在。聊天的七个拖拽清理监听也仅在拖拽时注册。划词通过最近的消息元素定位，取消消息列表遍历和历史查找；相同选区不触发重复状态更新，触摸模式不监听划词。

修复聊天 CSS 的打包路径：由原始文件拼接改成 esbuild 解析 @import，确保共享的菜单、时间分隔、减少动态效果与键盘焦点样式实际进入生成资源。桌面页面和聊天 iframe 共用样式来源。

本轮收敛验证：类型检查、构建、chat-message-flow、原生 chat-context-menu、local-file-preview-electron 与 chat-render-performance 通过。覆盖页面空白/时间/按钮/弹窗标题不触发菜单，选区复制、草稿与附件保留，五次菜单开关后监听数回归基线，拖拽结束清理监听。受控性能采样：帧间隔 P95 17.2ms、空闲 P95 17.3ms、无 long task、挂载 81 条消息。

上一轮精简验证：3 项时间/草稿单元测试、类型检查、构建、chat-message-flow、chat-react 与原生 chat-context-menu 通过。覆盖单一复制入口、选区复制、复制失败重试、纯文字划词添加、草稿保留、不发送消息、键盘与窄窗口/深色显示。最后一轮原生测试首次启动未取得聊天 frame，重跑通过。

上一轮验证：56 项相关单元测试、类型检查、聊天资源构建、chat-message-flow、chat-react、chat-context-menu（隔离 Electron 与原生剪贴板）、Muse 工作区布局矩阵、chat-render-performance 通过。浅色、深色、435px 窄窗口截图在 test-results/message-*.png。流式 fixture 本轮采样 P95 约 17.7ms、无 long task；不代表真实服务或原生整窗性能保证。没有自动发送真实聊天内容。

## 2026-10-30：设置原地展开与全局交互统一

本节为当前行为，替代后文旧版“分类入口 → 二级设置页”的导航描述。通过 Computer Use 再次查看 Muse 的通用、电脑使用界面：借鉴浅灰圆角分组、线条图标、名称/说明/控件层级。Muse 自身仍有部分子页面；本项目按用户要求进一步去掉设置内部的二次页面跳转。

- Being、Portal、Town、模型、外观与阅读、通用保留六个分类。Being 与 Town 直接显示配置；Portal 本机配置、诊断就地展开；模型选择/编辑保留概览，在其下展开。移除重复的模型“配置”入口及失效的二级页面样式。
- 每个分类只有一个纵向滚动容器，标题和关闭位置固定。连接保存成功停留当前分类；失败保留输入。模型草稿加入同一待保存事务，避免直接保存模型覆盖其他分类的草稿。切换分类不丢失已暂存的连接配置，关闭仍在原框确认。
- 统一分组 16px、控件 10px 圆角及圆头线条图标；Portal 运行摘要与本机配置之间留出明确间距。左下角菜单顶部的 Portal 状态入口保留。
- 共用 Dialog 的搜索、场景编辑、Town 发言/登记、Kit 安装、工具审批、插件弹窗采用 140ms 的开合过渡；权限和编辑菜单淡入 120ms。仅动画透明度/位移，不逐帧修改宽高。系统减少动态效果时，包括伪元素在内全部停用动画和过渡。
- 补齐通用键盘焦点样式，移除全局对键盘焦点的无条件隐藏。工作簿标签使用与设置/Town 一致的方向键、Home/End、单一 Tab 停靠点，并在切换文件时重置旧标签与选中格。通讯录登记使用共用可滚动表单布局，短窗口下按钮可达。

验证：类型检查、聊天资源构建、1156 项单元测试通过（33 项平台/原生条件跳过）；settings-navigation、workspace-layout（完整工作区与 Muse 设置矩阵）、ui-interaction、menu-keyboard、model-catalog-ui、subagent-model-ui、chat-render-performance、chat-lazy-resources 通过。设置截图覆盖 1440×960、760×500、435×746 及深色主题。同步迁移了 electron-smoke、permissions-packaged、portal-runtime-e2e、town-ui、town-sdk 的旧设置入口与成功关闭断言；这些原生脚本仅通过语法检查，本轮没有重新运行其完整安装包流程。

本机 Chrome fixture 单次流式回归观测：132 帧、帧间隔 P95 17.5ms、idle P95 16.7ms、未观测到 long task、挂载 81 条消息。这是受控页面测试，不能据此证明 Electron 原生窗口拖动/空闲卡顿已彻底解决。没有替换用户的已安装客户端，没有发送真实消息、切换真实模型或执行第三方授权。

## Muse / Grok Bot 的可借鉴之处

- 设置有稳定的外框、导航和关闭位置。内容变化通过内部滚动处理，不随页签重新居中。
- 动效幅度小、持续时间短，主要变化在透明度和位置。
- 已显示的信息在切换面板时保持稳定，避免每次重新出现加载占位。

观察界面不能证明对方的内部架构或帧率。本次没有获取两款应用的私有代码，也没有把截图中的私人内容写入仓库。
