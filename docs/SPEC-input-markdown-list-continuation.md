# SPEC: 输入框 Markdown 输入体验

- 日期：2026-09-24（最终版，待 Marvic 拍板）
- 状态：DRAFT
- 类型：体验小需求（fork → PR 路线，weiguo 侧合不合他定）

## 1. 一句话

输入框支持部分结构化 markdown：**打字时就看到结构**（标题、圆点、序号、缩进），Shift+Enter 续行自动带标记，Tab 升降级。屏幕上看到的是渲染后的样子，底下存和发给 AI 的永远是源码 `# 标题` 原文。

## 2. 打字时渲染（跟 Codex）

拍板依据：实测 Codex 打字渲染 `#` 标题的体验后，选「跟 Codex」——prompt 框是 being 主人的高频入口，打字时有反馈是对的。Cursor 只做续行不渲染是 VS Code 开发者工具血统的产品选择，不是技术上限。

### 2.1 支持集：四个，定死

being 对话场景——交代任务、列清单、贴需求、描述问题——全是**结构**而非**样式**：

| # | 输入 | 屏幕上变成 |
|---|------|-----------|
| S1 | `# ` 及 `## ` `### ` 多级 | `#` 消失，该行变标题：**颜色+字重表达层级，字号只微调**（防行高跳）。多级标题跟渲染一起做，不单独纠结 |
| S2 | `- ` / `* ` / `+ ` | 连字符/星号变**圆点 `•`** |
| S3 | `1.` `2.` `3.` | 保持数字序号，缩进对齐 |
| S4 | Tab / Shift+Tab | 两空格升降级，圆点/序号随之嵌套出层级 |

### 2.2 不做

粗体斜体、表格、代码块、引用块、checkbox 续行——粘贴原样进，发送后渲染端照常处理。判断依据：being 场景用不到，保持轻。

### 2.3 技术路线：复用，不造轮子

- **textarea 底座不动**（光标、输入、续行全部保留），上方叠一层**复用消息气泡同款 `Markdown` 渲染组件**（marked 路线）的实时预览，文本同源自 textarea
- 不引入 CodeMirror、不换 contenteditable
- 白送的收益：打字时看到的样子 = 发出去的样子，同一个组件渲染，天然一致，无两套渲染漂移
- **两层对齐是验收硬标准**：预览层与 textarea 逐行锁定行高，光标行与渲染行不得错位；字号微调产生的行高差用行高补齐抹平

## 3. 续行行为规格（对齐 CodeMirror `insertNewlineContinueMarkup`）

| # | 规则 | 行为 |
|---|------|------|
| R1 | 续行 | Shift+Enter 时，当前行是列表项 → 新行插入同缩进+同类型标记：有序 `N.`/`N)` → `N+1`；无序 `-`/`*`/`+` → 同符号 |
| R2 | 多级继承 | 嵌套列表续行时，新行继承**当前层级**的完整前缀，不塌缩到父级 |
| R3 | 空行降级退出 | 光标在**只有标记没有内容**的项上 Shift+Enter → 删一层标记：多级时降一级，单级时清空退出列表 |
| R4 | Tab 缩进 | 光标在行首或列表标记前按 Tab → 插入 2 空格（升一级）；Shift+Tab → 删 2 空格（降一级）；行中 Tab 不劫持 |
| R5 | 无干扰 | 纯 Enter=发送、IME 组词中、代码围栏内 → 零行为变化 |
| R6 | 有序重排 | 受管操作（R1/R3/R4）后，光标所在同级有序块重编 1…n；手改序号、粘贴、普通 Enter 发送不重排；代码围栏内不参与 |

## 4. 视觉规格

自动插入的 `2.` 和手打的 `1.` **不做任何来源性视觉区别**——渲染只看文本内容，输入方式不进元数据。发送后与手打消息完全一致。

## 5. 交互细节（已逐条对照现有代码验证）

- **IME 五重守卫已存在**（page.tsx onKeyDown：composing.current / isComposing / keyCode 229 / compositionEnd+50ms）。续行逻辑挂进 Shift+Enter 分支必须复用同一组守卫
- **自动增高已存在**（桌面 6 行 / 移动 4 行封顶后内部滚动）
- **光标复位**：插入前缀后光标落标记后，同一帧内 setSelectionRange
- **undo 限制**：受控 textarea 改 value 破坏原生 undo（已接受；反馈强烈则改 execCommand insertText）
- **行高跳动**：打 `#` 那一刻行高会跳——Codex 手感处理得很顺，照着调

## 6. 实现路线

分两步：

1. **续行第一阶段（MR 已在本地分支完成）**：裸 textarea + 正则前缀解析。纯函数 `parseListPrefix` / `buildContinuation` / `renumberOrderedLists`（list-continuation.ts），改动仅 page.tsx keydown 分支 + 一个纯函数文件。渲染端、bridge、main 进程零改动
2. **打字渲染第二阶段**：`Markdown` 组件套 overlay 容器，onChange 同步文本，字体/字号/行高/内边距与 textarea 逐项对齐写进组件常量；textarea 文字色透明、caret-color 可见；预览层 pointer-events: none

## 7. 验收用例

续行（第一阶段）：

1. `1. 甲` Shift+Enter → `2. `，连打到 `5.` 每次都续（报障场景）
2. `- 甲` → `- `；`* 甲` → `* `；`1) 甲` → `2) `
3. 多级：子级 `- 乙` Shift+Enter → 新行继承子级缩进 + `- `
4. 只剩 `3. `（无内容）→ 单级退出；多级时只降一级
5. 行首 Tab → 2 空格；Shift+Tab → 删 2 空格
6. IME 组词中 / 代码块内 → 零行为变化
7. 纯 Enter 发送、发送后渲染与今日完全一致
8. renumber：首行前插 / 项内回车 / 空项退出 / Tab 往返后，同级有序序号连续；多级、无序、围栏内见 tests/list-continuation.test.mjs

打字渲染（第二阶段）：

9. 打 `# ` → `#` 消失、行变标题（颜色+字重），光标不飘、行高不跳
10. 打 `- ` → 变圆点 `•`；`1. ` 保持数字
11. Tab 升降级时圆点/序号嵌套出层级
12. 两层对齐：预览层与 textarea 逐行锁定，打字到第 5 行不错位
13. 输入预览的样子 = 发送后消息气泡的样子（同组件）
