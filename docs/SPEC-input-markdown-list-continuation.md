# SPEC：聊天输入框的 Markdown 编辑

- 版本：2026-09-25，按当前代码整理
- 范围：聊天输入框；发送后的消息渲染沿用现有逻辑

## 目标

输入框只绘制一份可编辑文字。草稿和发送内容始终保留 Markdown 源码；输入时仅为标题和列表提供轻量视觉反馈。光标、选区与文字由同一编辑器表面绘制。

## 显示规则

| 源码 | 输入时显示 |
|---|---|
| 行首 `# `、`## `、`### `（前面允许 0～3 个空格） | 隐藏整个标记和后随空白，不留缩进；标题与对话消息共用字号 22、20、17 px、字重 550、行高和字距，颜色与正文一致。 |
| 单独的 `#`、四级以上标题 | 显示原文。 |
| 行首 `- `、`* `、`+ ` | 显示成与已发送消息相同的圆点：一级实心、二级空心、三级起方形；文字每级缩进 22 px。无有效父项且缩进超过 Markdown 允许值时显示源码。 |
| 行首 `1. `、`2) ` 等 | 序号保留，`)` 在编辑时显示为 `.`，源码不变；文字每级缩进 22 px。已发送消息各级仍使用十进制序号。 |
| 粗体、行内代码、链接、引用、表格等 | 输入阶段显示源码。 |
| 反引号或波浪线围栏内 | 全部显示源码，不转换标题或列表标记。 |

编辑器文档本身不删除标记。例如屏幕显示 `标题`，草稿和发送数据仍为 `# 标题`。拼写检查关闭，避免源码隐藏时出现独立的红色波浪线。桌面输入框最多约六行，窄屏最多约四行，超出后内部滚动。

## 编辑规则

| 操作 | 行为 |
|---|---|
| Enter | 发送草稿；输入法组词中及刚结束组词时不发送。 |
| Shift+Enter | 在有内容的列表项续行，有序项生成下一序号并重排同一列表的同级项；空行两侧的有序项仍属同一列表，普通段落才将列表隔开。光标位于列表标记内部时从标记后续行，不拆坏标记；空列表项退出或降一级。在文首退出空有序项时保留可输入的普通首行，后续序号恢复。其他位置换行。 |
| Tab / Shift+Tab | 普通文字及代码围栏每次增减两个空格。列表项按前一条同级项的内容起点缩进，Shift+Tab 退回上一层；序号随层级重排。没有可作为父项的前一条同级列表项时，Tab 保持原样且焦点留在输入框，避免发送成代码块。多行选区逐行按同一规则处理。已有父项时可继续建立更深层级，代码不设层级上限。 |
| 逐字退格或选中删除有序项 | 数字、点号或后随空格一旦被删到不再构成有序标记，后续序号立即更新，无须删掉换行；重新打回标记时序号也恢复。整项删除同样即时重排，删除和改号属于同一次撤销。独立列表与代码围栏内文字不受影响。 |
| 代码围栏内 | Shift+Enter 不续列表；Tab / Shift+Tab 只调整源码缩进。 |
| 输入法组词中 | 不执行列表续行和受管缩进。 |
| 切换或恢复外部草稿 | 更新输入内容并开启新的撤销历史；`⌘Z` 不带回上一个草稿。 |

## 实现与验收

使用 CodeMirror 的单层可编辑视图。装饰只改变可见文字，完整 Markdown 保存在编辑器文档中。已发送消息仍由现有 `marked` 渲染器处理。当前装饰在每次文档变化时扫描全文；本地浏览器测试中，万行围栏代码末尾一次 CodeMirror 更新约 2 ms，不含后续绘制，也不是低端设备的性能保证。

验收重点：`# ` 后继续输入时标记不冒出；标题与正文左边缘对齐且没有重影；中文输入法、点击落点、选区、撤销、长代码、列表快捷键和发送源码均正常。自动化覆盖标题装饰、代码围栏、列表三级缩进与标记、浏览器中的对齐与单层绘制；真实窗口的输入法体验仍需人工确认。输入框只预览此表列出的标题与列表样式，粗体、链接、表格和四级以上标题仍显示 Markdown 源码，因此它们与发送后的排版不会逐项相同。非规范源码（如普通段落紧接 `2. `，或两空格缩进的有序项）也仍可能和发送后的 Markdown 解析不同。
