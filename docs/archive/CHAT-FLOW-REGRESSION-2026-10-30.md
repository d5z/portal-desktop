# 对话流修复与回归记录

日期：2026-10-30。通过 Computer Use 直接操作 Portal Desktop 开发客户端，在独立场景「对话流回归 1030」中发送测试文本，并核对客户端接口日志。没有只用浏览器模拟结果替代客户端实测。

## 修复内容

- 同一场景只显示最新一条等待气泡；正文正在流式输出时隐藏等待气泡。工具产物、错误和详细过程仍保留。
- 打断分隔线从一开始就位于新用户消息之前，与服务端历史顺序一致，避免历史确认后重新移动。
- 消息入场动画不再改变几何位置；延迟到达的程序滚动事件不会仅凭内容增长错误地解除跟随。用户主动上滚仍保留阅读位置。
- 部分回复保持正常文字对比度，移除重复的“已中断”徽标。停止失败提示使用紧凑的一行提示和重试入口。
- 兼容部署中的空响应 HTTP 200 和 204 停止回执；202、否定 JSON、错误流 ID、无效 JSON 和网络失败仍保留恢复/重试能力。
- 同场景、本次请求之后的持久化停止记录可以确认丢失的回执；旧记录和其他场景记录不能停止当前流。
- 停止确认与 SSE 清理交错时不再创建第二条已停止记录；持久化停止分隔线到达后不再重复显示本地状态行。
- 启动时对过期的活动流预取快照重新核对，避免历史已经完成、旧快照仍在回放的短暂重影。
- 回放缓冲区先完整刷新到气泡，再交给轮询，避免刷新后先显示第一个 token、等待下一次网络事件才恢复全文。

## 补充：等待气泡切换到首字的抖动

用户继续反馈首字出现时抖动。进一步测量发现前面的去重修复没有覆盖等待行与正文行的几何差异：等待气泡高 40px、底部间距 16px；正文首行高 57.195px、底部间距 24px。历史满屏且贴底时，替换会让上一条用户消息和气泡顶端一起上移 25px。

修复让等待气泡与正文共享响应式内边距、首行最小高度、最小宽度、圆角和外间距；等待状态的场景标签也放到正文标签对应的位置。没有增加高度过渡动画或计时延迟。

通过 Computer Use 操作同一聊天渲染器测量：

| 情况 | 用户消息纵向位移 | 气泡顶端位移 | 气泡高度变化 |
| --- | --- | --- | --- |
| 修复前，满屏历史 → 首行短句 | -25px | -25px | +17.195px |
| 修复后，满屏历史 → 首行短句 | 0px | 0px | 0px |
| 修复后，435px 窄窗口 → 首行短句 | 0px | 0px | 0px |
| 修复后，空对话 → 单字 | 0px | 0px | 0px |
| 修复后，满屏历史 → 单字 | 0px | 0px | 0px |
| 修复后，435px 窄窗口 → 单字 | 0px | 0px | 0px |

三个单字场景的气泡宽度变化也都是 0px，不会先缩小再扩展。`chat-flow-manual.mjs` 新增“追加单字”以及逐帧 `firstTokenShift` 指标，能够复测首字切换；多行正文后续正常增高不属于此零位移断言。

另外直接在真实客户端发送“气泡切换修复复测”，确认加载修复并显示单字“好”。本轮 `typecheck`、`lint:chat-hooks`、`build:chat`、`git diff --check` 及 11 项显示/滚动相关单元测试通过。测量记录：`test-results/chat-flow-2026-10-30/first-token-metrics.json`；客户端截图：`first-token-after-text-small.png`。
